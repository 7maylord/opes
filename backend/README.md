# OPES backend

The OPES backend is a NestJS API and persistent worker for evidence-backed business payments. It owns tenant isolation, document intake, payable verification, treasury policy, Circle wallet operations, Arc contract execution, reconciliation, notifications, and the audit ledger.

See the [root README](../README.md) for the product overview and [RUNBOOK.md](RUNBOOK.md) for production operations.

## Responsibilities

- Exchange Privy access tokens for OPES sessions and resolve organization-scoped roles.
- Provision one Circle operator wallet and one verified Arc vault/escrow pair per organization.
- Ingest documents from uploads, Resend inbound email, vendor portals, watched storage, Odoo, and ERPNext.
- Store document hashes, model extractions, confirmed facts, procurement evidence, and vendor-address history.
- Run duplicate checks and deterministic three-way payable matching.
- Generate advisory agent decisions, then enforce treasury policy independently before execution.
- Execute and reconcile direct, recurring, and milestone-escrow payments.
- Track liquidity actions through Gateway/CCTP adapters and optional destination swaps.
- Post balanced ledger entries, export lineage, create workspace notifications, and send supplier payment advice.

## Runtime shape

The same image runs in two modes:

| Process | Command | Work |
|---|---|---|
| API | `pnpm start:dev` / `node scripts/start.mjs` | HTTP requests, auth, signed webhooks, presigned document operations |
| Worker | `pnpm start:worker:dev` / `OPES_PROCESS=worker node scripts/start.mjs` | Outbox jobs, provisioning, extraction, payments, liquidity, reconciliation, email |

PostgreSQL is the source of truth and queue boundary. Runtime access uses a `NOSUPERUSER NOBYPASSRLS` login so row-level security remains effective. Documents use Railway’s S3-compatible Storage Bucket in production and MinIO locally.

## Local setup

From the repository root:

```sh
pnpm --dir backend install --frozen-lockfile
cp backend/.env.example backend/.env
docker compose -f backend/docker-compose.yml up -d
pnpm --dir backend db:migrate
pnpm --dir backend start:dev
```

Run the worker in a second terminal:

```sh
pnpm --dir backend start:worker:dev
```

The easier full-stack command is `./scripts/dev.sh --worker`. It prepares the runtime database role and starts the API on `http://localhost:3004`.

## Configuration

[.env.example](.env.example) is the authoritative variable list. Its groups cover:

- Privy server authentication
- Circle developer-controlled wallets
- runtime and migration PostgreSQL roles
- Railway Bucket / local MinIO storage
- DeepSeek document extraction and advisory decisions
- Resend inbound mail and outbound payment advice
- connector-secret encryption
- Arc and destination-chain RPC endpoints
- optional liquidity signer and Base Sepolia USDT swap bindings

Leave optional route groups empty to keep those capabilities disabled. Do not invent a Resend webhook secret; use the `whsec_...` value generated by Resend.

## Main API surfaces

All tenant routes resolve the bearer session and organization context before touching business data.

| Area | Examples |
|---|---|
| Identity and tenancy | auth exchange, session, onboarding, organizations, members, invitations |
| Agent setup | agent state, Circle wallet provisioning, verified Arc resource bindings |
| Evidence | vendors, payout addresses, uploads, extraction, procurement records, invoice matching |
| Intake | workspace inbox, Resend webhook, vendor portal, watched bucket, Odoo/ERPNext sync |
| Decisions | invoice verification, agent recommendation, override, authorization, execution |
| Agreements | recurring subscriptions/cycles and escrow agreements/milestones |
| Treasury | position, policy actions, liquidity, reconciliation, owner controls |
| Audit | workspace records, ledger, notifications, outbox operations |

The OpenAPI-derived frontend workspace types are regenerated from the repository root with:

```sh
pnpm --dir frontend api:generate
```

## Accounting connectors

Owners and admins configure connectors through the workspace or `POST /organizations/:organizationId/accounting-connectors`.

- **Odoo 19:** tenant root URL, database name, and a JSON-2 API key for vendors, purchase orders, receipts, and vendor bills.
- **ERPNext:** site root URL plus an API key and API secret for Suppliers, Purchase Orders, Purchase Receipts, and Purchase Invoices.

Credentials are encrypted at rest and redacted from API responses. Setup, sandbox permissions, sync behavior, and settlement writeback are documented in [RUNBOOK.md](RUNBOOK.md#accounting-sandboxes).

## Validation

```sh
pnpm lint
pnpm build
pnpm test --runInBand
pnpm test:e2e --runInBand
```

The unit suite covers domain rules and provider boundaries. The e2e suite requires PostgreSQL and verifies migrations, RLS, tenant isolation, idempotency, and complete financial workflows.

## Production

Production runs as separate `opes-api` and private `opes-worker` Railway services rooted at `backend/`, using [railway.json](railway.json). Both attach to PostgreSQL; attach bucket credentials wherever document jobs run. Only the API receives a public domain and Resend webhook traffic.

The deployed API is [opes.up.railway.app](https://opes.up.railway.app). Public probes are `/health` and `/ready`; the allowed browser origin is [opes.maylord.xyz](https://opes.maylord.xyz).

Interactive Swagger documentation is served at `/docs`; the OpenAPI JSON document is available at `/docs/openapi.json`. Use the appropriate authorization control in Swagger for a Privy exchange token, OPES session token, or operations token. Signed provider webhook routes document their header-based authentication separately and do not use bearer sessions.
